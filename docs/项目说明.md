# crm-dashboard 项目说明（权威文档）

> **商家名片系统**：`card.html`（业务端，H5 页面）让用户填写/管理电子名片，`admin.html`（管理端）供运营按平台统计、查看并管理所有名片用户；数据持久化到**腾讯云 TDSQL（MySQL 协议）**，头像/二维码图片存**阿里云 OSS**。
>
> 本文档为当前版本的**权威说明**（2026-10-16 更新）。项目已从早期"微信小程序"形态收敛为**纯 H5 + 管理后台**，**不再有小程序端**。

**核心原则：前后端分家。**
- 后端 = `backend/`（Java + Maven，编译产物 `backend/target/` 自动忽略）
- 前端 = `frontend/`（纯静态 HTML，浏览器直接打开）
- 部署时 `deploy_prod.bat` 会把 `frontend/` 页面自动同步到 `backend/.../static/`，随 jar 同源发布，**免 Nginx、免跨域配置**。

> **已移除**：早期的微信小程序端（`frontend/wechat-app/`）与 `wechat-miniprogram.zip`。现在业务完全由 `card.html` 承担。

## 二、技术栈

## 三、如何启动

### 前置
1. **JDK 8**（推荐；只有 11/17 也能跑）
2. **Maven 3.6+**（或用 `backend/mvnw.cmd` 免安装）
3. **数据库**：H2（零配置）/ 本机 MySQL / 生产 TDSQL 三选一

### 模式 A：H2 快速体验（最省事，无需任何数据库）
```bat
cd backend
mvn spring-boot:run -Dspring-boot.run.profiles=local
:: 或免装 Maven： mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local
```
看到 `Started CRMApplication` 即成功，服务在 `http://localhost:8080`。
- 管理端 Key：`local-admin-key`
- 微信/OSS 为占位假数据，**真实图片上传不可用**，但开发模式登录 + 名片增删改正常
- H2 控制台：`http://localhost:8080/h2-console`（`sa`/`sa`，JDBC `jdbc:h2:mem:crm`）

### 模式 B：连本机 / 自建 MySQL
1. 建库：`CREATE DATABASE crm DEFAULT CHARACTER SET utf8mb4;` 再导入 `backend/src/main/resources/crm.sql`
2. 启动：
```bat
cd backend
mvn spring-boot:run
```
默认 `localhost:3306/crm`，账号 `root`/`root`（可用环境变量 `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASS` 覆盖，见第五节）

### 模式 C：生产（腾讯云 TDSQL，当前目标）
```bat
:: 项目根目录执行（Windows）
scripts\deploy_prod.bat
```
脚本会：① 同步 `frontend/` 页面到 `static/` ② 打包 jar ③ 用 `prod` profile 启动。
- 数据库默认指向 `146.56.210.13:3306/crm`，敏感项（`DB_PASS`、`OSS_*`、`ADMIN_KEY`）在脚本"配置区"或环境变量里填
- 启动后访问：
  - 业务端 `http://146.56.210.13:8080/card.html`
  - 管理端 `http://146.56.210.13:8080/admin.html`（Key 填你的 `ADMIN_KEY`）

### 启动自检
```
GET /admin/stats/platform      带请求头 X-Admin-Key: <key>   → {"success":true,...} 即正常
GET /user/dev-login?unionId=t1                            → 返回含 jwt 字段即登录链路正常
GET /card                带 Authorization: <jwt>          → 返回当前用户名片
```

## 四、主要接口

### 业务端（`card.html` 使用；JWT 鉴权，请求头 `Authorization`）
```
GET  /user/dev-login?unionId=xxx   开发模式登录，换 JWT（绕过微信，当前唯一可用登录方式）
GET  /user/current                当前用户信息
POST /user/update                 更新用户基础资料
GET  /card                        当前用户名片
POST /card/update                 编辑名片（body 见 CardUpdateDTO）
POST /card/clear                  清空名片（字段置 NULL）
GET  /card/user/{jid}            扫码查看他人名片
POST /file/img/upload             图片上传 OSS（multipart，≤1MB）
```

### 管理端（`admin.html` 使用；请求头 `X-Admin-Key`）
```
GET    /admin/users?page=1&size=20&keyword=&platform=   用户分页列表
GET    /admin/users/{id}                                 用户详情
PUT    /admin/users/{id}                                 修改用户（写审计日志）
DELETE /admin/users/{id}                                 软删除（is_delete=1，写审计）
GET    /admin/stats/platform                              各平台用户统计
GET    /admin/audit-logs?page=1&size=50                    审计日志
```

### 数据链路（card.html → 服务端）
```
dev-login 换 JWT
  → /card        读 TDSQL
  → /card/update 写 TDSQL
  → /card/clear  清空 TDSQL
  → /file/img/upload  传头像/二维码到 OSS，返回相对路径随 /card/update 落库
```

## 五、敏感信息 / 环境变量（务必阅读）

代码库中**无任何真实密钥**，全部走"占位符 + 环境变量"。

| 环境变量 | 默认值 | 用途 | 敏感性 |
|---|---|---|---|
| `DB_HOST` | `localhost`（prod 默认 `146.56.210.13`） | 数据库地址 | 低 |
| `DB_PORT` | `3306` | 数据库端口 | 低 |
| `DB_NAME` | `crm` | 库名 | 低 |
| `DB_USER` | `root`（prod 默认 `crm`） | 数据库账号 | 中（生产勿用 root） |
| `DB_PASS` | `root`（prod 默认 `crm`） | 数据库密码 | **高** |
| `OSS_AK` / `OSS_SK` | `xx` | 阿里云 OSS 密钥 | **极高**（建议 RAM 子账号最小权限） |
| `OSS_ENDPOINT` | `xx` | OSS 域名 | 中 |
| `OSS_IMG_PREVIEW` | `xx` | 图片预览前缀 | 低 |
| `ADMIN_KEY` | `admin-secret-key` | 管理端鉴权 Key | **高**（等于后台万能钥匙，生产务必改） |
| `WX_APPID` / `WX_APPSECRET` | `your-wechat-appid` | 小程序登录用（当前 card.html 走 dev-login，**用不到**） | 可留空 |

**注入方式（Windows）：**
```bat
set DB_PASS=你的真实密码
set ADMIN_KEY=强随机key
scripts\deploy_prod.bat
```

**规范：** 真实密钥永不入库；团队共享走 `application.yml` 占位符 + 环境变量，个人差异走 `local`。

## 六、已知安全弱点（上线前需处理）

1. **`/user/dev-login` 无访问密钥**：任何人知道 unionId 即可登录并写库。**生产强烈建议加 `X-Access-Key` 校验**（待办）。
2. **CORS 全开放**：`WebConfig` 里 `Access-Control-Allow-Origin: *` 且允许 `Authorization`/`X-Admin-Key`。同源托管后页面本身不受影响，但管理接口若被外部站点调用仍有风险，生产建议做来源白名单。
3. **`ADMIN_KEY` 默认值弱**：`admin-secret-key` 可被猜，生产必须换强随机值。
4. **H2 控制台**：仅 local 模式，无鉴权（`sa/sa`），确认只在本机使用。
5. **fastjson 1.2.47**：存在已知反序列化漏洞（CVE），建议升级到 1.2.83+。
6. **JWT 无服务端黑名单**：登出靠前端清 token，属设计取舍。

> 生产部署前，第 1、2、3 项建议优先处理。

## 七、数据库说明

- **两张表**：
  - `tb_user`：用户/名片。`id`(varchar32 主键)、`is_delete`(软删除 1删/0正常)、`union_id`、`platform`(所在平台)、名片字段（phone/wechat_id/email/description/greeting/biz_type/biz_name/msg_link/qr/platform 等）
  - `tb_audit_log`：管理员操作审计（`action`、`before_json`/`after_json`、`operator`）
- 字符集 utf8mb4；时区东八区（`serverTimezone=Asia/Shanghai`）
- 软删除：MyBatis-Plus 逻辑删除，`ModifyHandler` 自动填 `created/updated`

## 八、代码导读（读后端从哪入手）

```
请求 → controller/*（校验/返回 Result）
     → service/impl/*（业务）
     → mapper/*（MyBatis-Plus，几乎不写 SQL）
     → entity/po/*（对应表）
返回 → 统一 Result<T>（success/message/data）

横切关注点：
- CrmAuthHandler        JWT 拦截（业务端；/admin/** 走 Key）
- RateLimiterAspect      方法级限流（@SelfLimiter）
- ModifyHandler          自动填充 created/updated/软删除
- GlobalExceptionHandler 统一异常 → Result
- GlobalUserCache / QrHolder 登录态 / 二维码上下文
```

推荐顺序：`CRMApplication` → `WebConfig` → `UserController`(dev-login) → `CardController` → `AdminServiceImpl`(审计) → `JwtUtil`。

## 九、FAQ

**Q1：`Could not resolve placeholder` / 数据库连不上？**
确认 profile：local→H2；prod→`DB_*` 环境变量/脚本配置区填对；MySQL 已启动、`crm` 库已导入 `crm.sql`。

**Q2：页面"加载失败"？**
按序排查：① 后端在跑吗（8080）② 接口地址对吗（注意 http/https 一致）③ Key 对吗 ④ 浏览器控制台看跨域/证书。

**Q3：图片上传 500？**
图片走 OSS，需真实 `OSS_AK/OSS_SK/OSS_ENDPOINT/OSS_IMG_PREVIEW`。缺配置时文字数据仍可保存，仅图片降级本地预览。

**Q4：端口 8080 被占用？**
`application-prod.yml` / `application.yml` 改 `server.port`，前端连接条同步改。

**Q5：`annotaition` 包名？**
历史拼写错误（应为 annotation），**不要改**，改了要动 4 个文件 + 全部 import，收益为负。
