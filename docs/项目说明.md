# crm-dashboard 项目说明（新手版）

> 商家名片小程序后台 + 管理端。基于微信小程序的电子名片服务：用户在小程序里填写名片信息（姓名、业务、联系方式、所在平台、微信二维码等），管理端按平台统计、查看并管理所有用户。
>
> 本文档为整理后的**权威说明**。日期：2026-09-23。

## 三、如何启动（新手重点章节）

### 前置条件
1. **JDK 8**（推荐；本机若只有 JDK 11/17 也能启动，项目 pom 里已补了 jaxb 依赖兼容）
2. **Maven 3.6+**（或直接用 `backend/` 目录下的 `mvnw.cmd` 免安装）
3. **数据库**：二选一
   - 模式 A（推荐新手）：**H2 内存库**，零配置，`application-local.yml` 自带
   - 模式 B：本机 **MySQL 5.7+**

### 模式 A：无数据库快速体验（H2，最省事）

```bat
:: 打开 cmd / PowerShell，进入后端目录
cd D:\WareHouse\Project\小程序\crm-dashboard\backend
mvn spring-boot:run -Dspring-boot.run.profiles=local
:: 或者免装 Maven：
mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local
```

看到 `Started CRMApplication` 即成功，服务在 `http://localhost:8080`。

- H2 控制台：`http://localhost:8080/h2-console`（JDBC URL `jdbc:h2:mem:crm`，用户 `sa`，密码 `sa`）
- 此模式下**管理员 Key 是 `local-admin-key`**（见 `application-local.yml`）
- 微信/OSS 用的是假数据，**真实微信登录和图片上传不可用**，但可通过"开发模式登录"体验完整流程

### 模式 B：连 MySQL（正式体验 / 生产）

**第 1 步：建库建表**

打开 MySQL 客户端（Navicat / 命令行均可），执行 `backend/src/main/resources/crm.sql`。
该脚本会自动 `DROP` 并重建 `tb_user`、`tb_audit_log` 两张表，库名默认 `crm`。
> 注意：如果库 `crm` 不存在，先执行 `CREATE DATABASE crm DEFAULT CHARACTER SET utf8mb4;` 再导入。

**第 2 步：启动**

```bat
cd D:\WareHouse\Project\小程序\crm-dashboard\backend
mvn spring-boot:run
```

默认连接 `localhost:3306/crm`，账号 `root` / 密码 `root`（可在 yml 里改或用环境变量覆盖，见第五节）。

**第 3 步：打开前端页面**

浏览器直接打开（无需服务器）：

| 页面 | 文件 | 用法 |
|---|---|---|
| 用户端 | `frontend/card.html` | 顶部连接条填 `http://localhost:8080` + 用户标识 → 点"连接"（开发模式登录），然后填写名片 |
| 管理端 | `frontend/admin.html` | 接口地址 `http://localhost:8080` + 管理员 Key（默认 `admin-secret-key`，local 模式为 `local-admin-key`） |

> 两个 HTML 都是单文件应用，双击打开即可。跨域已由后端 `WebConfig` 允许（`Access-Control-Allow-Origin: *`）。

### IDE 启动（IntelliJ IDEA）

1. 打开项目时**选择 `backend/` 文件夹**作为项目根（让 IDEA 识别 `pom.xml`）
2. 等 Maven 索引完成
3. 运行 `com.pfh.crm.dashboard.CRMApplication`
   - H2 模式：Run Configuration 里加 VM 参数 `-Dspring.profiles.active=local`
4. 如果 IDEA 里 Java 版本不对：Project Structure → SDK 选 8/11

### 启动自检（确认一切正常）

启动后依次访问：

```
GET http://localhost:8080/admin/stats/platform    带上请求头 X-Admin-Key: <你的key>
→ 返回 {"success":true,"message":"OK","data":{}} 即正常

GET http://localhost:8080/user/dev-login?unionId=test-1
→ 返回带 jwt 字段的结果即登录链路正常
```

## 五、⚠ 敏感信息 / 隐藏信息说明（务必阅读）

整理时已逐文件排查，**代码库中没有任何真实密钥**，全部采用"环境变量占位符 + 默认值"方式。以下为所有涉及敏感信息的点位：

### 5.1 环境变量（`backend/src/main/resources/application.yml`）

| 环境变量 | 默认值 | 用途 | 敏感性 |
|---|---|---|---|
| `DB_HOST` | `localhost` | MySQL 地址 | 低 |
| `DB_PORT` | `3306` | MySQL 端口 | 低 |
| `DB_NAME` | `crm` | 库名 | 低 |
| `DB_USER` | `root` | 数据库账号 | **中**（生产勿用 root） |
| `DB_PASS` | `root` | 数据库密码 | **高**（生产务必覆盖） |
| `WX_APPID` | `your-wechat-appid` | 微信小程序 AppID | 中 |
| `WX_APPSECRET` | `your-wechat-appsecret` | 微信小程序 AppSecret | **极高**（泄露=小程序沦陷） |
| `OSS_AK` | `xx` | 阿里云 OSS AccessKeyId | **极高** |
| `OSS_SK` | `xx` | 阿里云 OSS AccessKeySecret | **极高** |
| `OSS_ENDPOINT` | `xx` | OSS 域名 | 中 |
| `OSS_IMG_PREVIEW` | `xx` | 图片预览域名/前缀 | 低 |
| `ADMIN_KEY` | `admin-secret-key` | 管理端鉴权 Key | **高**（等于后台万能钥匙） |

**怎么注入真实值（Windows 示例）：**

```bat
:: 启动前设置环境变量（仅当前 cmd 窗口有效，不落盘、不进 git）
set DB_PASS=你的真实密码
set WX_APPID=wx你的真实appid
set WX_APPSECRET=你的真实appsecret
set ADMIN_KEY=你的复杂随机key
mvn spring-boot:run
```

**规范（新手请遵守）：**
1. 永远不要把真实 AppSecret / OSS AK / SK / 生产数据库密码写进任何 `yml` 或提交到 git
2. 本地个人配置想持久化时，**新建 `application-local.yml` 并加进 `.gitignore`**（当前 `.gitignore` 未忽略该文件，因为它是 H2 开发配置且无敏感信息；如果你往里写真实密钥，请先加一行 `backend/src/main/resources/application-local.yml` 到 `.gitignore` 并 `git rm --cached` 它）
3. 团队共享配置走 `application.yml` 的占位符 + 环境变量；个人差异走 local

### 5.2 管理端鉴权 Key（双模式）

- **生产/默认**：`application.yml` 里 `crm.internal.admin-api-key`，默认 `admin-secret-key`，可用 `ADMIN_KEY` 环境变量覆盖
- **本地 local 模式**：固定 `local-admin-key`（写在 `application-local.yml`，无敏感问题）
- 前端 `frontend/admin.html` 默认显示 `xx` 占位，需手动填入对应模式的 Key
- 审计日志里的 `operator` 字段只记录 Key 前缀（脱敏设计，见 `AdminServiceImpl`）

### 5.3 已排查、确认无敏感问题的文件

| 文件 | 结论 |
|---|---|
| `run_boot.bat`（现 `scripts/`） | 含**本机绝对路径**（JDK `C:\Program Files\Java\jdk1.8.0_131`、Maven `D:\MAVEN\apache-maven-3.8.8`），是机器绑定脚本，**不进 git**；换机器必须改 |
| `frontend/card.html` | 默认接口地址 `http://localhost:8080`，无密钥 |
| `frontend/admin.html` | 默认 `xx` 占位，无真实 Key |
| `docs/sql/tmpseed.sql` | 测试数据脚本，含假手机号/邮箱（`13800000001`、`example.com`），非真实 PII，**不进 git** |
| `docs/logs/*.log` | 运行日志，历史上可能打印过完整请求；整理后**不进 git**，定期清理 |
| `wechat-miniprogram.zip` | 小程序源码包，解压后请检查 `app.js/config` 是否含 AppID（正常应有，确认无 AppSecret 即可入库；当前 git 状态已作为重命名跟踪） |
| `pom.xml` | 无敏感项；注意 `fastjson 1.2.47` 存在已知反序列化漏洞（CVE），建议后续升级 |

### 5.4 已知安全弱点（整理时记录，供后续改进）

1. **CORS 全开放**：`WebConfig` 里 `Access-Control-Allow-Origin: *` + 允许 `Authorization`、`X-Admin-Key` 任意来源。管理端页面若被公开访问，任何站点都可能调你的管理接口。生产建议限制来源域名
2. **`ADMIN_KEY` 默认值偏弱**：`admin-secret-key` 是明文可猜的默认值，生产必须换
3. **H2 控制台暴露**：local 模式 `/h2-console` 无密码（sa/sa 写在配置里），仅限本机
4. **fastjson 版本过旧**：1.2.47，建议升到 1.2.83+ 或迁移 Jackson
5. **JWT 无服务端黑名单**：登出依赖前端清 token，属设计取舍，知晓即可

## 六、数据库说明

- **两张表**：
  - `tb_user`：用户/名片表。`id`(varchar32, 主键)、`is_delete`(软删除：1=删,0=正常，查询默认排除已删)、`union_id`(微信标识)、`platform`(所在平台：微信/小红书/抖音等)
  - `tb_audit_log`：管理员操作审计（`action`、`before_json`/`after_json` 快照、`operator`）
- **字符集**：utf8mb4（中文必开）
- **时区**：JDBC URL 带 `serverTimezone=Asia/Shanghai`，统一东八区
- **软删除**：MyBatis-Plus 逻辑删除，`Delete` 注解 + 修改处理器 `ModifyHandler` 自动填 `created/updated`
- 升级老库用的 ALTER 语句在 `crm.sql` 末尾（已注释，按需取消注释执行）

## 七、代码结构导读（新手看后端从哪入手）

```
请求 → controller/* （参数校验、返回 Result）
     → service/impl/* （业务逻辑）
     → mapper/* （MyBatis-Plus，几乎不写 SQL）
     → entity/po/* （对应数据库表）
返回 → 统一 Result<T> 封装（success/message/data）

横切关注点：
- CrmAuthHandler   JWT 拦截器（用户端鉴权；/admin/** 走 Key）
- RateLimiterAspect + @SelfLimiter  方法级限流（Guava）
- ModifyHandler    自动填充 created/updated/软删除
- GlobalExceptionHandler  统一异常 → Result
- GlobalUserCache  登录用户缓存（unionId→用户信息）
- QrHolder         二维码上下文（扫码跳转链路）
```

读代码推荐顺序：`CRMApplication` → `WebConfig`（拦截器/跨域）→ `UserController` → `CardController` → `AdminServiceImpl`（审计逻辑）→ `JwtUtil`（登录态）。

## 九、常见问题（FAQ）

**Q1：启动报 `Could not resolve placeholder 'DB_PASS'` 或数据库连不上？**
A：确认模式 A 带了 `-Dspring-boot.run.profiles=local`；模式 B 确认 MySQL 已启动、账号密码对、`crm` 库已导入 `crm.sql`。

**Q2：页面提示"加载失败"？**
A：按 `admin.html` 的提示顺序排查：① 后端在跑吗（访问 8080）② 接口地址对吗（`http://localhost:8080`，注意 http/https 一致）③ Key 对吗（模式匹配：local→`local-admin-key`，默认→`admin-secret-key`）④ 浏览器控制台看是否跨域/证书问题。

**Q3：图片上传 500？**
A：图片走阿里云 OSS，需要真实 `OSS_AK/OSS_SK/OSS_ENDPOINT/OSS_IMG_PREVIEW`。local 模式里是假数据，上传必然失败，属预期行为。

**Q4：微信登录失败？**
A：真实 `WX_APPID/WX_APPSECRET` 未配置，或小程序在微信后台配置的**服务器域名未包含你的后端域名**（必须是 https）。联调期请用 `/user/dev-login`。

**Q5：端口 8080 被占用？**
A：`application.yml` 改 `server.port`，前端连接条同步改。

**Q6：`annotaition` 包名拼写？**
A：历史遗留拼写错误（正确为 annotation），**不要改**，改了要动 4 个文件 + 所有 import，收益为负。已在新结构中保留原样。

**Q7：为什么 wechat.zip 从 resources 移走了？**
A：它是小程序源码包，不参与后端构建，放在 `src/main/resources` 会被打进 jar 包（浪费 500KB 且语义混乱）。现移到 `frontend/wechat-app/wechat-miniprogram.zip`，解压后用微信开发者工具打开。代码中无任何引用（已搜索确认），迁移零风险。
